# Evaluation

Measures whether embedding retrieval plus NVIDIA Nemotron actually beats keyword matching at
placing products into a marketplace taxonomy, and whether the confidence score it reports is
trustworthy enough to gate human review.

## Files

| File | What it is |
|---|---|
| `dataset/products.jsonl` | Canonical products, cached so every run is reproducible and offline |
| `labels.csv` | The ground truth. `expected_category_id` is filled by a human |
| `results.md` | Generated by the runner, do not edit by hand |

## The dataset

104 products, 26 each from four public apparel stores: Allbirds, Girlfriend Collective,
Naked & Famous Denim and Taylor Stitch. They were chosen for different naming conventions, not
for being easy.

## Labelling

```sh
uv run catalogbridge eval bootstrap --store allbirds.com --store girlfriend.com \
  --target meridian_apparel --per-store 26 --i-own-this-catalog
```

Fill `expected_category_id` in `labels.csv` using the ids from
`catalogbridge targets --id meridian_apparel`. The `suggestion` column holds the keyword
retriever's top three guesses as a starting point.

Re-running bootstrap preserves any `expected_category_id` you have already filled in.

### Who labelled this set

All 104 rows were labelled in one pass by reading each product's title, its seller-assigned
product type, and the opening of its description. Every judgment call carries a short reason in
the `notes` column, 16 rows in total. Those are the rows to check first if you only have time to
check some.

**This labelling has a weakness you should know about.** It was done by an AI assistant, not by a
retail merchandiser. For most of this catalog that is fine, because a Tree Runner is a sneaker and
a beanie is a hat whoever is looking. But where the call was genuinely arguable, an AI labeller and
an AI classifier may share the same instinct and agree for the same wrong reason, which flatters
the accuracy number. The honest way to read these results is: the labels are a reasonable
first pass, and the 16 flagged rows deserve a human eye before the numbers are quoted anywhere.

The arguable ones, so they are findable:

- Taylor Stitch's long-sleeve waffle "Organic Cotton Crew" filed as a t-shirt, because the
  taxonomy has no long-sleeve tee category
- The "Maritime Shirt Jacket" filed as outerwear, following the seller, though it is an overshirt
- Allbirds "Cruiser Slip On" filed as a sneaker rather than a flat
- Allbirds "Breezer" and "Lounger" styles filed as flats rather than sneakers
- A knit rugby shirt filed as a shirt rather than knitwear

**`expected_category_id` is never auto-filled.** An earlier version of this harness pre-filled it
from the keyword retriever when that retriever returned exactly one candidate. That is leakage: the
keyword baseline would have been scored against labels it generated itself. The guess belongs in
`suggestion`, where a human can accept or reject it, and nowhere else.

If no category genuinely fits a product, leave `expected_category_id` empty. Unlabelled rows are
excluded from every metric rather than counted as failures.

## Running

```sh
uv run catalogbridge eval run --target meridian_apparel
python eval/run_eval.py
```

Keyword retrieval runs without a Nebius key. Embedding retrieval and mapping are skipped with a
warning when `NEBIUS_API_KEY` is unset, so the baseline column can be produced before the model
column.

## What is measured

**Retrieval** is the ceiling on everything downstream. If the correct category never reaches the
shortlist, no model can recover it.

- `recall@k`: the correct category is somewhere in the top k
- `top-1`: the top candidate is correct, which is the no-model baseline
- `no candidate`: nothing was retrieved at all
- `mean rank`: where the correct answer sits when it is found

**Mapping** measures what Nemotron does with that shortlist: category accuracy, how many products
it declines to map, what fraction of required attributes it fills, and how many it flags.

**Calibration** is the metric that justifies the whole review design. If accuracy is high when the
model is confident and low when it is unsure, the threshold is doing real work and a reviewer's
attention lands where it matters. If both are similar, the confidence score is decoration and the
threshold should go. `review_catches_errors` is the share of wrong answers that were flagged, which
is the number a vendor actually cares about.

## Known weaknesses

Recorded here because an evaluation that hides them is not worth running.

**The keyword baseline is representative, not optimal.** It stems plurals and scores on category
names and keywords, deliberately excluding the path so that "Women" does not match every women's
category. It has no bigram awareness, so "Short Sleeve Crew" retrieves Shorts, since "sleeve"
is not considered. These are real keyword-matching failures and they have been left in.

**The dataset contains near-duplicates.** Several products differ only by colour: nine bodysuits
across three styles, three colourways of one legging. Whatever the model does on one of those it
will do on all of them, which over-weights those product families. Consider labelling one
colourway per family and leaving the rest blank.

**The taxonomy was extended twice after seeing the data.** First bodysuits, shorts, leggings,
sports bras and swimwear, once Girlfriend Collective's catalog had nowhere to go. Then hoodies and
sweatshirts, once 13 of the 104 products turned out to be French terry crewnecks and hoodies that
would otherwise have been mislabelled as knitwear. Both are taxonomy completeness rather than model
tuning, and both raised the keyword baseline rather than lowering it, but they happened after the
data was seen and should be known.

For the record, the baseline moved as the taxonomy got more honest:

| Taxonomy | Top-1 | Recall@5 | No candidate |
|---|---|---|---|
| 28 categories, hoodies filed as knitwear | 72.1% | 90.4% | 8.6% |
| 30 categories, hoodies have a home | 76.0% | 94.2% | 4.8% |

**Four stores is not a representative sample** of apparel retail, let alone of e-commerce. The
numbers describe these 104 products and nothing more.
